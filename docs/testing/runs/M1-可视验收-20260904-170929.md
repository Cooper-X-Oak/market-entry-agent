## 缺陷

### F01 — Source 成功请求被前端显示成失败

- 严重度：Major，阻断 M1-SRC-01 与 M1-SRC-02。
- 观察：两个 POST 都返回 201，数据库和 MinIO 均成功；UI 随后显示 `Cannot read properties of null (reading 'reset')`，Source 只能在硬刷新后出现。
- 代码位置：`apps/web/components/source-manager.tsx:13-14`。
- 原因：`await apiClient(...)` 后继续读取 `event.currentTarget`；事件派发结束后该引用为 `null`，因此 `reset()` 抛错，后续 `router.refresh()` 未执行。
- 影响：用户无法判断操作是否成功，重复提交可能形成重复来源。
- 修复方向：在 `await` 前保存稳定的 form 引用，成功后 reset 并 refresh；给 URL 与上传成功路径增加浏览器测试。

### F02 — Source 时间跨时区导致 Hydration mismatch

- 严重度：Major，阻断 ENV-01 的“无 Hydration 红屏”。
- 观察：无扩展 Agent Browser 中，SSR 为 `2026/9/4 09:18:43`，客户端为 `2026/9/4 17:18:43`。
- 代码位置：`apps/web/components/source-manager.tsx:15`。
- 原因：SSR 与客户端在不同系统时区调用 `toLocaleString('zh-CN')`，输出不确定。
- 影响：Next.js 开发环境出现 Recoverable Error 浮层，相关子树在客户端重新生成。
- 修复方向：使用固定时区的共享 formatter，或把本地化时间推迟到 hydration 之后。

此前用户 Chrome 截图里的 `data-immersive-translate-page-theme="light"` 仍属于浏览器扩展注入；本次无扩展复现的是另一条、独立的项目时间文本差异。两类问题可以同时存在。
