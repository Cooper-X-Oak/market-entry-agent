# 模块纠正契约与工程验收（2026-09-08）

机器入口为 [模块纠正索引](模块纠正索引.json)。当前 **ENGINEERING_PASS / CANDIDATE_READY_NOT_DEPLOYED**，指受控外部响应下的完整工程验收；五地区真实业务均未通过。详细报告见 [远端工程验收与部署方案](../../.grok/verify-artifacts/20260908-module-correction/remote-validated/远端工程验收与部署方案.md)。历史失败报告保留。

```text
实际 Nest HTTP → Mission / Domain Event → 实际 Temporal Workflow / Worker
 → Agent Context / Connector → Provider → 原业务 Schema
 → 引用及内容校验 → 独立调用审计（含已验证输出）
 → 准备结果缓存 → 所有权与取消检查 → 短事务幂等提交
 → 主表 → Projector → HTTP 重读 / ZIP + Manifest
非原文内容 → 独立语义审查 → 引用摘录逐字检查 → 原业务门
取消与新执行 → Mission 行锁及父子执行所有权
关闭任务 → 流式遍历对账 → Mission 终态（周期不等于收敛时限）
```

远端独立 PostgreSQL 16 + pgvector，独立 Temporal 服务；API / Worker / Projector 使用不同数据库角色。58 项完整套件与 3 项 Workflow 测试、类型检查、构建均退出 0。1005 项对账等待 15.002 秒，处理 17.089 秒，总计 32.091 秒。原文、翻译、概括、推断、反对证据和不同联系方式有正反例；语义审查不宣称对任意自然语言形成形式化证明。

迁移仅在隔离数据库执行。既有业务数据库、服务及依赖保持原位；发布候选含驱动断连补丁，须在定向部署中备份、核对后原子替换。登录鉴权使用测试身份，真实 Provider/网页和 UI 未据此验收。

旧喀山失败现场保留；当前只读对账影响检查显示一条 CANCELLED 但业务仍 running/compiling 的 Mission，部署后拟纠正为 failed，不更改历史内容或 Mock 来源标签。

## 统一执行约束

Provider 暂时故障最多3次总尝试，单次90秒、总截止240秒、最多6000输出token；SDK首轮内部重试强制关闭，Temporal主链Activity最多1次；输出/引用/取消/超时不自动重试。语义审查是另一次独立记录的 Provider 调用，遵守相同有限重试；并发业务去重不保证并发模型请求只发生一次。
